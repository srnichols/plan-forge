Forge-Claw

An experimental, opt-in chat front door that routes approved work into governed execution lanes and asks Forge-Master to reason over project context.

What it is

Forge-Claw is a host-level package, not a project setup feature. It is not installed or started by setup. Telegram is the first channel adapter. OpenClaw remains an alternative integration and the existing outbound notification bridge continues to work.

Read the full Forge-Claw guide on GitHub and the threat model on GitHub.

Architecture

The channel adapter receives and formats messages. The dispatcher checks identity and policy, then places jobs on local, remote, or Kubernetes lanes. Each lane uses the configured AgentRuntime; GHCP is the default, with BYOK alternatives. A project's home lane owns its checkout and canonical memory. Remote workers dial outbound to the dispatcher. Forge-Master supplies reasoning and may return proposals, but does not execute them.

Safe quick start

Install Node.js 22.12 or newer and use an existing Plan Forge framework checkout. Keep the host home outside project repositories, store credentials outside committed config, and review the generated example before starting.

pforge claw init --example single-host --out <dir>
pforge claw doctor --home <dir>
pforge claw start --home <dir>

Initialization is explicit. A successful offline doctor check does not validate live provider authentication, Telegram access, or Kubernetes policy enforcement.

Command discovery

Run pforge claw commands --markdown for the registered chat command catalog or pforge claw commands --json for structured metadata. Chat /help is filtered by caller role and topic. The registered /forget command is currently unavailable.

The CLI has eight subcommands: init, doctor, status, start, worker, service, dev, and commands.

Approvals and budgets

Mutating jobs require a single-use, expiring approval bound to the requesting chat and an allowlisted approving identity. Forge-Master's proposedActions are proposals only; an adapter must authorize and create a separate job, and Forge-Claw's approval policy still applies.

Reported USD and premium-request usage are tracked independently. Unknown usage stays null, not zero; configured unknown-usage limits can hold further mutating jobs until an owner releases them.

Lanes and workers

Lanes are configurable local, remote, or Kubernetes execution targets. Labels drive placement constraints; an opt-in lane must be enabled before it accepts new jobs. Each project specifies a home lane for its checkout and Plan Forge MCP calls.

Remote workers enroll with a short-lived, single-use code and connect outbound. Use wss:// except on loopback. Workers do not listen for inbound connections and do not receive a reusable dispatcher credential for job execution.

Deployment choices

Run a single-host dispatcher, add remote workers on supported macOS, Windows, or Linux hosts, or deploy Kubernetes Jobs using the example Kustomize overlay. The service command integrates with launchd, systemd, or Windows Task Scheduler. Kubernetes RBAC is namespace-scoped; hostname egress restrictions require CNI-specific support beyond plain NetworkPolicy IP rules.

For current operating steps, platform caveats, and pending validation results, see the complete guide on GitHub.

Limitations

  • Telegram is the only shipped inbound channel adapter.
  • /forget is registered but unavailable; platform matrix entries remain pending.
  • There is no forge_claw_* MCP tool family and no npm publish.
  • Git worktrees are not OS sandboxes; use stronger host or container isolation where required.
  • Do not treat offline tests as evidence of live GHCP/BYOK, Telegram, TLS, or CNI behavior.
